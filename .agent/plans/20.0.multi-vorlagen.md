# 20.0 — Mehrere Vorlagen pro Nutzer (bis zu 4)

⚠️ **Medium** — Touches DB, backend router, ADK tool + instructions, and three
frontend surfaces (modal, sidebar, chat composer). Each change mirrors an
existing pattern, so risk is moderate but the surface is wide.

## Goal

Generalise today's **one** Projektanalyse-Vorlage per user into **up to 4**
freely-named templates.

Decisions locked with the customer:
- **Invocation = Both** — natural-language matching *and* a UI picker. These
  converge: the UI picker sends a human-readable command that the NL path
  already parses, so there is exactly **one** backend resolution mechanism.
- **Slots = create on demand (0–4)** — user starts with their existing template
  and can add up to 3 more. Needs create/delete UI + empty/limit states.
- **Migration** — each user's existing `analysis_templates` row becomes their
  first template (`position = 0`, name `"Projektanalyse"`). No data loss.
- **Naming** — user-chosen; default for a freshly-added slot is `"Vorlage N"`.

## Task 1 — DB migration: new `user_templates` table + data migration

**New migration** `supabase/migrations/0025_user_templates.sql`.

```sql
create table public.user_templates (
  id         uuid primary key default gen_random_uuid(),
  user_id    uuid not null references auth.users(id) on delete cascade,
  name       text not null,
  questions  text[] not null default '{}',
  position   smallint not null,            -- 0..3, ordering in UI/picker
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (user_id, position)
);

alter table public.user_templates enable row level security;
create policy "owner full access" on public.user_templates
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

create index user_templates_user_idx on public.user_templates(user_id, position);

-- Hard cap of 4 templates per user (defence in depth; API also enforces).
create or replace function public.enforce_max_user_templates()
returns trigger language plpgsql as $$
begin
  if (select count(*) from public.user_templates where user_id = new.user_id) >= 4 then
    raise exception 'Maximal 4 Vorlagen pro Nutzer erlaubt';
  end if;
  return new;
end;
$$;
create trigger user_templates_max_4
  before insert on public.user_templates
  for each row execute function public.enforce_max_user_templates();

-- Migrate existing single templates → position 0, name 'Projektanalyse'.
insert into public.user_templates (user_id, name, questions, position)
  select user_id, 'Projektanalyse', questions, 0 from public.analysis_templates;

-- New-user seed: replace the analysis_templates insert in handle_new_user with
-- one user_templates row (keeps the default questions + name 'Projektanalyse').
create or replace function public.handle_new_user()
returns trigger language plpgsql security definer set search_path = public as $$
declare
  fname text := coalesce(nullif(trim(new.raw_user_meta_data->>'first_name'), ''), null);
  pname text;
begin
  pname := case when fname is null then 'Mein Projekt' else fname || 's Projekt' end;
  insert into public.projects (user_id, name) values (new.id, pname);
  insert into public.user_templates (user_id, name, questions, position)
    values (new.id, 'Projektanalyse', public.default_analysis_questions(), 0);
  return new;
end;
$$;
```

> `analysis_templates` is **kept** (read-only legacy) until Task 7 cleanup so
> the migration is reversible. `default_analysis_questions()` is reused as-is.

**Apply** via `mcp__supabase__apply_migration` to project `gbnpzuoidkzuahggujwu`
("RAG").

**Validation:**
- `select user_id, name, position from user_templates order by user_id, position;`
  → every pre-existing user has exactly one row, name `Projektanalyse`, pos 0,
  questions identical to their old `analysis_templates` row.
- Insert-cap test: as a test user with 4 rows, a 5th insert raises
  `Maximal 4 Vorlagen pro Nutzer erlaubt`.
- RLS test: querying with another user's JWT returns 0 rows.

## Task 2 — Backend router: full CRUD (`backend/app/routers/templates.py`)

Replace the two `projektanalyse` endpoints with list/create/update/delete.
Keep the `prefix="/api/templates"`.

```python
class TemplateOut(BaseModel):
    id: str
    name: str
    questions: list[str]
    position: int

class TemplateCreate(BaseModel):
    name: str | None = None
    questions: list[str] = Field(default_factory=list, max_length=50)

class TemplateUpdate(BaseModel):
    name: str | None = None
    questions: list[str] | None = Field(default=None, max_length=50)
```

- `GET  /api/templates` → `list[TemplateOut]`, ordered by `position`.
- `POST /api/templates` → create. Server computes next free `position`
  (0..3); **409** if user already has 4. Default `name = "Vorlage {n+1}"`,
  `questions` cleaned (strip/drop empties).
- `PUT  /api/templates/{template_id}` → update name and/or questions
  (`.eq("id", id).eq("user_id", user_id)`; 404 if no row). `name` must be
  non-empty if provided; `questions` may be empty list (draft template).
- `DELETE /api/templates/{template_id}` → delete (scoped to user_id); 204.

All scoped by `current_user_id`. Use `supabase()` service client exactly like
the old code.

**Validation (curl with test user JWT):**
- `GET` → 1 template (`Projektanalyse`).
- `POST {}` ×3 → `Vorlage 2/3/4`; a 4th `POST` → **409**.
- `PUT /{id} {"name":"Termine","questions":["Frage A"]}` → reflected on re-GET.
- `DELETE /{id}` → 204; re-GET shows it gone and a new `POST` succeeds again.

## Task 3 — ADK tool: target a named template (`projektanalyse_tool.py`)

Generalise `run_projektanalyse` to accept an **optional** `template_name`.

- `_load_templates(user_id) -> list[dict]` reads all rows from
  `user_templates` (id, name, questions, position), ordered by position.
- Resolution inside `run_projektanalyse(tool_context, template_name: str | None = None)`:
  1. If `template_name` given → case-insensitive, trimmed match on `name`;
     fall back to substring match. No match → return
     `{"answers": [], "notice": "Keine Vorlage namens «X». Verfügbar: ..."}`.
  2. If `template_name` empty/None:
     - exactly one template → use it.
     - multiple → prefer the one named `Projektanalyse` (back-compat); if none
       such → `{"answers": [], "notice": "Mehrere Vorlagen vorhanden: A, B, C. Welche?"}`.
     - zero → existing "keine Vorlage hinterlegt" notice.
- Questions empty for the resolved template → notice "Vorlage «X» hat keine
  Fragen."
- Otherwise unchanged: `fanout_rag_specialist(...)` + grounding/citation
  aggregation. Return `{"answers": [...], "template_name": <resolved name>}`.

Update the `FunctionTool` docstring so the orchestrator knows about the optional
`template_name` arg. Keep the no-arg path working (UI sends a name, but generic
"Projektanalyse erstellen" still resolves via rule 2).

> Honours memory `project_chat_batch_questions_fanout` — fan-out per question is
> preserved; we do not collapse the orchestrator/rag_specialist split.

**Validation:**
- Unit-ish: monkeypatch `_load_templates` to return 3 templates; assert
  `template_name="termine"` resolves the `Termine` row; unknown name yields a
  `notice` listing the 3 names; `None` with a `Projektanalyse` present resolves
  it.
